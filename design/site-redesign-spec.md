# mini-spring 官网重构设计方案

> 版本 v1.0 · 仅设计层面，不含代码实现
> 目标站点：GitHub Pages 上的 mini-spring 文档站
> 设计目标：专业、精致、大气，达到同类开源项目官网的主流水准

---

## 一、现状分析

### 1.1 技术底座

| 项目 | 现状 |
|---|---|
| 框架 | VitePress 1.6.3（静态站点生成器） |
| 部署 | GitHub Actions → GitHub Pages，base 路径 `/mini-spring/` |
| 主题 | 默认主题 + 单文件 `custom.css` 覆写（约 600 行） |
| 视觉取向 | 强复刻 Drizzle ORM 设计语言：近黑/浅灰表面、单一品牌色、细边框卡片、小圆角、紧凑排版 |
| 国际化 | 根路径简体中文 + `/en/` 英文，路由同构 |
| 搜索 | VitePress 本地搜索（MiniSearch），已做中文文案翻译 |

### 1.2 现有页面清单（共 20 个渲染页面）

**门户层**
- `index.md`（中文首页）、`en/index.md`（英文首页）—— 结构完全对称

**文档层（中文 9 篇 / 英文 9 篇镜像）**

| 分组 | 页面 |
|---|---|
| 前言 | 为什么手写 Spring、项目总览：两条实现路径 |
| 快速开始 | 环境与运行 |
| IoC 容器 | 容器启动全流程、Bean 生命周期、三级缓存解决循环依赖、IoC 全景类图 |
| 进阶特性 | AOP 原理与实现、事件监听与发布 |

### 1.3 首页现状区块（自上而下 6 段）

1. Hero：徽章胶囊 + 主标题（渐变强调）+ 副标题 + 双按钮 + 克隆命令复制条
2. Features：6 张特性卡（IoC / DI / AOP / 三级缓存 / 事件 / 扩展点），每卡带独立强调色

5. Roadmap：4 步学习路径卡
6. 底部 CTA：「开始你的手写之旅」

|---|---|---|

### 1.5 诊断：核心问题

| # | 问题 | 影响 |
|---|---|---|
| P1 | **信息层级过扁**：全站只有「首页 + 一组文档」两层，导航仅 3 项（文档 / IoC 类图 / GitHub） | 站点的叙事容量被压在一个页面里，访客只能"进文档"，无法按意图分流 |
| P2 | **门户与文档割裂**：首页大量卡片内容（特性、双路径、学习路径）在文档中没有对应落点，看完首页进文档即丢失上下文 | 转化路径断裂，跳出率高 |
| P3 | **缺"决策型"内容**：没有「两条路径怎么选」的对比页，双路径只靠首页两张卡描述 | 目标用户（想学 Spring 的人）最大的决策成本未被承接 |
| P4 | **缺"工具型"内容**：134 个类没有可检索的类参考索引 | 学习者读文档时无法独立查证，"地图"缺失 |
| P5 | **缺"信任型"内容**：无更新日志、无关于/致谢、无贡献指南 | 开源项目的活跃度与可信度无法被感知，也不利于外部贡献 |
| P6 | **首页视觉节奏单调**：6 个区块全是「标题 + 等宽网格卡片」的同一句式，缺少尺度变化与视觉锚点 | 长首页的中后段缺乏推进力，显得平 |
| P7 | **视觉体系未成文**：所有数值散落在 `custom.css` 里，没有设计令牌（Design Token）层 | 新增页面会持续发散，无法规模化 |

| 维度 | 目标 |

## 三、整体页面结构与布局

### 3.1 四层信息架构

```
第 1 层 · 门户层
└── 首页（叙事 + 分流入口）

第 2 层 · 分流层（本次新增的核心价值层）
├── 两条路径对比   ← 承接"我该从哪开始"
├── 学习路线       ← 承接"怎么学完"
└── 类参考索引     ← 承接"这个类干什么的"

第 3 层 · 文档层（在原有基础上重组分组）
├── 快速开始（3 篇，由 1 篇扩展）
├── 架构总览
├── 核心原理 · IoC（5 篇）
└── 进阶特性（2 篇）

第 4 层 · 支撑层
├── 常见问题 FAQ
├── 更新日志
├── 关于与致谢
├── 贡献指南
└── 404
```

### 3.2 全局布局骨架

三种布局并存，由页面类型决定：

| 布局 | 适用 | 结构 |
|---|---|---|
| **门户布局（Home）** | 首页 | 全宽 Hero → 交替背景分区（白 / 灰）→ 全宽 CTA，内容最大宽度 1120px，正文 620px |
| **文档布局（Doc）** | 所有 guide 页 | 左侧栏 240px（吸顶可滚） + 正文 880px + 右侧大纲 200px（吸顶），三段式三栏 |
| **宽版布局（Page）** | 对比页 / 类参考 / 路线 / FAQ / 更新日志 | 无左侧栏，正文最大宽度 1080px，允许两栏网格与并排表格 |

**关键改进点：**
- 文档正文宽度从 880px 提升至 **920px**（中文每行 38–42 字最舒适，按 15px 字号换算），右侧大纲在大纲为空时自动让位
- 门户布局引入 **分区背景交替**（`--ds-bg` / `--ds-surface`），替代现在 6 个区块全同一底的平铺感
- 所有布局共享统一的 **8.5rem 顶部偏移**（导航 64px + 呼吸 72px），保证跨页视觉基线一致

### 3.3 页面高度节奏（首页）

首页从 6 段扩展为 8 段，并引入"尺度变化"制造节奏：

| 序 | 区块 | 视觉尺度 | 背景 | 目的 |
|---|---|---|---|---|
| 1 | Hero | 超大（标题 60px） | 渐变光晕 | 建立第一印象 |
| 2 | 数据条（新增） | 紧凑（4 个数字） | 灰底描边条 | 用客观事实建立信任 |
| 3 | 特性网格 | 中（6 卡） | 白底 | 功能全景 |
| 4 | 两条路径 | 中（2 大卡） | 灰底 | 核心决策 |
| 5 | 架构图预览 | 大（全宽图） | 白底 | 视觉锚点 |
| 6 | 代码一瞥（新增） | 中（左右对照） | 灰底 | 展示"代码可读" |
| 7 | 学习路径 | 紧凑（4 步） | 白底 | 行动指引 |
| 8 | CTA | 大 | 渐变收束 | 转化 |

## 四、各页面组成与层级

### 4.1 首页（强化版）

**区块 1 · Hero**
- 层级：徽章胶囊 → 主标题（2 行断行）→ 副标题（≤2 行）→ 主/次按钮 → 克隆命令条
- 新增：主标题下方一行 **"5 张架构图 · 134 个类 · 双语文档"** 的元信息行（13px，次要色）
- 新增：克隆命令条增加 **版本标签切换**（`v2.0` / `main`），让访客明确取哪一版
- 保留：渐变强调词、光晕背景

**区块 2 · 数据条（新增）**
- 4 个指标并列：`134` 个 Java 类 / `5` 张架构图 / `2` 条实现路径 / `9` 章文档
- 单行描边容器，数字 28px 等宽、标签 12.5px 次要色
- 作用：Hero 之后立刻给出"这是一份认真的工程"的信号

**区块 3 · 特性网格**（沿用现有 6 卡，做两处升级）
- 卡片增加 **第 4 行"对应章节"链接**，把首页与文档打通（解决问题 P2）
- 强调色从 6 种收敛为 **3 色循环**（品牌蓝 / 青 / 紫），红绿橙仅用于语义状态，避免"彩虹感"

**区块 4 · 两条路径**
- 保留编辑器窗口装饰头（已形成辨识度）
- 每张卡底部新增 **"进入此路径 →"** 主操作，替换现在的纯文字描述
- 新增第三列窄卡：**"不确定选哪个？看对比 →"**，导流至新对比页

**区块 5 · 架构图预览**
- 从单图升级为 **主图 + 4 缩略图**：主图 Bean 生命周期，下方 4 个缩略图可点击切换主图
- 图表容器增加 **"在新标签打开 / 下载 SVG"** 两个图标按钮（图标 16px，悬停才显形）

**区块 6 · 代码一瞥（新增）**
- 左右对照：左列 12 行源码片段（`DefaultSingletonBeanRegistry` 三级缓存核心），右列 3 条要点解读
- 作用：证明"代码均有注释、可读"，这是同类项目官网最有说服力的一屏

**区块 7 · 学习路径**
- 4 步保留，新增每步的 **预估投入**（如"30 分钟"）与 **产出物**（如"跑通 CircleTest"）
- 顶部增加一条横向进度轴，把 4 张卡串成一条线（解决问题 P6 的"卡片堆叠感"）

**区块 8 · CTA**
- 主标题 + 双按钮 + 一行次要说明（"Apache 2.0 · 欢迎 Star 与 PR"）

### 4.2 快速开始（由 1 篇扩展为 3 篇）

## 五、导航结构与交互方式

### 5.1 顶部导航（3 项 → 6 项）

| 位置 | 项目 | 行为 |
|---|---|---|
| 左 | Logo + 站名 | 回首页 |
| 中 1 | **文档** | 下拉菜单：快速开始 / 架构总览 / 核心原理 / 进阶特性（4 组，各带 1 行说明） |
| 中 2 | **对比** | 直达两条路径对比页 |
| 中 3 | **类参考** | 直达类参考索引 |
| 中 4 | **路线** | 直达学习路线 |
| 中 5 | **更多** | 下拉：FAQ / 更新日志 / 关于 / 贡献指南 |
| 右 | 搜索 → 语言切换 → 外观 → GitHub | 图标组，间距 4px，悬停显现 8px 圆角浅底 |

**交互细节：**
- 下拉菜单：`180ms` 缓出（ease-out），淡入 + 下移 4px，键盘上下键可导航，Esc 关闭
- 导航链接悬停：文字色从次要色 → 主色，**下划线宽 2px、偏移 6px**，用 scaleX 从中心展开
- 当前页导航项：常亮品牌色 + 底部 2px 指示条
- 滚动行为：向下滚动超过 80px 后导航背景从不透明转为 **92% 不透明 + 12px 背景模糊**，高度从 64px 收到 56px

### 5.2 左侧栏（分组 4 → 6）

- 分组标题：11.5px / 700 字重 / 0.09em 字距 / 大写，次要色（沿用现有规格）
- 当前页：左侧 2px 品牌色竖条 + 轻微底色，非仅靠颜色区分
- 新增 **"进度标记"**：已读章节在标题前显示一个 6px 圆点（本地记录，可选开启）
- 长列表：分组头可折叠，折叠态记忆在本地
- 移动端：侧栏抽屉从左侧滑入，宽度 280px，遮罩 `rgba(0,0,0,.4)`，支持边缘右滑关闭

### 5.3 右侧大纲

- 仅展示 H2 / H3，2 级缩进
- 当前章节：品牌色 + 左侧 2px 指示条，指示条在切换时做 160ms 位移过渡
- 大纲为空时：整个右栏让位，正文自动居中（避免右侧留白空洞）

### 5.4 页脚导航矩阵（新增）

从单行版权升级为 4 列矩阵：

| 列 1 · 文档 | 列 2 · 参考 | 列 3 · 项目 | 列 4 · 联系 |
|---|---|---|---|
| 快速开始 | 两条路径对比 | 更新日志 | GitHub |
| 架构总览 | 类参考索引 | 贡献指南 | Issues |
| 核心原理 | 学习路线 | 关于与致谢 | QQ 群 |
| 进阶特性 | FAQ | License | 邮箱 |

底行：Logo + `Apache License 2.0` + 版权 + 语言切换

### 5.5 局部交互清单

## 六、视觉风格规范

> 现有基线是「强复刻 Drizzle」：近黑表面 + 单一品牌色 + 细边框 + 小圆角 + 紧凑。这个方向本身是专业且克制的，**重构不推翻它，而是把它系统化并补足"大气"的那一半**——通过更大的尺度跨度、更明确的层级色、更完整的间距节奏来实现。

### 6.1 设计令牌（Design Token）

**8px 基准栅格**

| 令牌 | 值 | 用途 |
|---|---|---|
| `--ds-space-1` | 4px | 图标与文字间隙 |
| `--ds-space-2` | 8px | 行内元素间隙 |

| `--ds-space-8` | 72px | 区块上下内边距（桌面标准） |
| `--ds-space-9` | 96px | Hero 上边距、大区块呼吸 |

**关键间距决策**
- 首页区块上下内边距：桌面 `72px`，移动 `48px`（现为 40px，偏紧，是"不够大气"的直接原因）
- 卡片网格间隙：桌面 `16px`（现 14px），移动 `12px`

| 令牌 | 值 | 用途 |
|---|---|---|
| `--ds-radius-sm` | 6px | 标签、按钮内小元素、行内代码 |
| `--ds-radius` | 10px | 卡片、输入框、代码块（现 8px，提升至 10px 更精致） |
| `--ds-radius-lg` | 14px | 大卡、图容器、下拉菜单 |
| `--ds-radius-xl` | 20px | 大区块容器、模态框 |
| `--ds-radius-pill` | 999px | 按钮、徽章、胶囊 |
| `--ds-stroke` | 1px | 描边统一 1px（现部分 0.5px 在高分屏下过细） |
| `--ds-shadow-1` | `0 1px 2px rgba(0,0,0,.04)` | 卡片静态 |

### 6.4 完整状态矩阵（每个交互组件必备）

| 状态 | 视觉表达 |
|---|---|
| Default | 基础规格 |
| Hover | 描边加深 / 底色微亮 / 上移 1–2px |
| Active（按压） | 位移归零，仅保留底色加深 |
| Focus-visible | `0 0 0 3px --ds-brand-soft` 外环 + 描边转品牌色（**仅键盘触发**，鼠标点击不显示） |
| Disabled | 透明度 0.45，`cursor: not-allowed`，取消全部位移与阴影 |
| Loading | 按钮内文字换为 14px 旋转指示器，宽度锁定不变 |
| Empty | 居中线性图标 40px + 提示文案 13.5px 次要色 + 可选恢复操作 |
| Error | 描边 `--ds-danger` + 下方 12.5px 红字说明 |
| Selected / Current | 品牌色常亮 + 左侧或底部 2px 指示条 + `soft` 底 |

> 现状诊断：现有 `custom.css` 仅定义了 hover 一态（且多为颜色变化），focus-visible / disabled / empty / loading 完全缺失。这是"看起来像 Demo"与"像官网"的分水岭之一。

### 6.5 动效规范

| 场景 | 时长 | 缓动 |
|---|---|---|
| 颜色 / 描边变化 | 120ms | `ease` |
| 位移 / 上移 | 150ms | `cubic-bezier(.2,.8,.3,1)` |
| 下拉 / 抽屉展开 | 180ms | `ease-out` |
| 折叠面板高度 | 200ms | `ease-out` |
| 数字计数 | 800ms | `ease-out` |
| 页面切换 | 200ms | 淡入 + 上移 6px |

**纪律**：全部动效必须包在 `@media (prefers-reduced-motion: no-preference)` 内；位移幅度不超过 8px；不使用弹跳（bounce）曲线，保持克制。

### 7.1 断点体系

| 断点 | 宽度 | 主要变化 |
|---|---|---|
| XS · 手机 | < 640px | 单列；导航收为汉堡抽屉；侧栏抽屉化；表格转卡片；Hero 标题 38px |
| SM · 大手机/小竖屏 | 640–767px | 特性网格 2 列；数据条 2×2 |

### 9.2 实施优先级

|---|---|---|
| **P0 · 令牌落地** | 建立设计令牌层，把现有 `custom.css` 的散值映射过去，补齐 9 态交互与 focus-visible | 不改页面即可全站提质，是所有后续工作的地基 |

### 9.3 验收标准

| 维度 | 标准 |
|---|---|
| 内容 | 38 个页面全部有实际内容，无占位符；中英路由完全对称 |
| 结构 | 任意页面 ≤ 3 次点击可达；无孤立页面（每个页面至少 2 个入链） |
| 视觉 | 全站仅使用令牌定义的数值，无硬编码颜色；标题字重不超过 5 档 |
| 交互 | 15 个组件状态齐全；全部可键盘操作；`prefers-reduced-motion` 生效 |
| 响应式 | 360 / 480 / 768 / 1024 / 1280 / 1600 六档无横向溢出、无内容截断 |
| 可访问性 | 正文对比度 ≥ 4.5:1；无 `outline: none`；Lighthouse 无障碍 ≥ 95 |
| 性能 | 首屏 LCP < 2.0s（4G）；字体子集化后单文件 < 60KB；图片全部提供 SVG 或 WebP |

## 十、风险与设计层面的注意事项

| 风险 | 设计对策 |
|---|---|
| 页面翻倍导致维护成本上升 | 双语严格镜像，共享同一套组件与令牌；文档页统一页头/页尾组件，新增章节零成本 |
| 类参考页数据量大（134 条） | 设计为前端筛选而非分页；默认折叠 original 模块；表格密度用 44px 行高平衡 |
| 强调色收敛后特性卡区分度下降 | 用标签文字 + 图标承担区分，颜色只做辅助；三色循环已足够形成节奏 |
| 深色模式在新增页面易失控 | 所有令牌双主题成对定义；新页面禁止直接写颜色，必须走令牌 |
| 首页 8 段过长导致滚动疲劳 | 通过分区背景交替 + 尺度变化 + 数据条/代码一瞥两个"短区块"打断节奏 |
| 品牌蓝在暗色下对比度不足 | 暗色下品牌色提亮至 `#7aa2ff`（现有做法正确），并对按钮文字色做反色处理 |
